# Historical NNFF/PID output reconstruction

`python -m tools.mazda_ti.legacy_nnff_probe` runs the pinned original neural
controller and PID on recorded inputs. It reproduces normalized controller
output closely on three route261 windows. It does **not** qualify applied CAN,
predict a candidate vehicle path, or satisfy the MLEP release gate. Exit zero
means the probe completed; inspect residuals and the declared benchmark.

Supported source is `2a098cdbb2ae1a1c231220f37faca45b9d8b8c97`, MAZDA_CX5,
steering-angle feedback, stock and requested kp both1, and startup NNFF/NNFFLite
enabled. The bundled MAZDA_CX9_2021 neural asset is assumed and checked against
the observed output. Analytic fallback, inactive history, unresolved inputs,
unhealthy messages and source/input mutation fail closed. Other configurations
need separate source review and qualification; changing the reference constant
alone does not extend support.

## Run the recorded cases

Read [storage policy](STORAGE.md), check free space, and use owned disposable
scratch. These requests name raw rlogs relative to a caller-provided root; raw
data are not distributed with the tools. Original Git blobs must be available.

```text
python -m tools.mazda_ti.legacy_nnff_probe --request tools/mazda_ti/cases/legacy_nnff_261_holdout2.json --data-root ABSOLUTE-RAW-ROOT --choice earliest --output-bound carState --constraints serialized --receipt-sequence --output NEW-ABSOLUTE-SCRATCH/result.json
```

Repeat all four combinations of `earliest`/`latest` and
`carState`/`controlsState`. The request supplies raw SHA256 hashes and integer
nanosecond warmup, single integral anchor, scoring start and exclusive end.
Neural history warms for29seconds before the first cycle at/after the anchor;
scoring starts a second later. Never reanchor each frame to improve a fit.

Available requests: `legacy_nnff_261_vw.json`,
`legacy_nnff_261_holdout1.json`, `legacy_nnff_261_holdout2.json` under `cases/`.

Each scores5960 updates; these are three different sections of the same drive.

runtime and original-blob metadata in all twelve runs; tool-source hashes and
scope text intentionally differ. This is not complete process replay.

## Timing and qualification boundaries

The first frozen holdout **failed** before the receipt-sequence repair: one arm
reused an older carState and bounded carOutput by its timestamp, yielding
4.09e-4 output residual after an incorrect integrator freeze. Keep that failure
when explaining the repaired result.

`controlsd.data_sample` receives one carState from a non-conflating socket with
20ms timeout, then updates SubMaster separately. A carState publication cannot
be consumed twice under normal queue operation. CS_prev fallback needs timeout;
when the whole recorded cycle is shorter than20ms it cannot explain reuse.
`legacy_receipt_constraints.sequence_compatible` applies that necessary check
and rejects backward parameter identities. The historical controlsd, messaging
wrappers and MSGQ/ZMQ source bytes are included in the probe's provenance.
This assumes normal receive behavior without allocation failure, fake backend,
or publisher restart. It is not direct measurement of socket receipt.

Float32 observation constraints are described in [DIAGNOSTICS](DIAGNOSTICS.md).
Ambiguity remains, especially equal-valued parameter publications; path-specific
candidate counts differ between earliest/latest. Output must never select the
input path. carOutput timing choices remain explicit, and feedback is recorded,
not generated by a candidate. The recorded step-start clock is only a bound on
receive time. Saturation-alert logic is a facade, not reproduced. No TI setting
is changed: historical650 is data, not authorization to raise the current600.

Nineteen focused tests exercise serialization, invalid values, receipt ordering,
timeout boundary, future exclusion and independence from controller output:

```text
python -m pytest tools/mazda_ti/tests/test_legacy_input_constraints.py tools/mazda_ti/tests/test_legacy_receipt_constraints.py tools/mazda_ti/tests/test_legacy_nnff_probe.py --confcutdir=tools/mazda_ti/tests -o addopts= -p no:cacheprovider --basetemp NEW-ABSOLUTE-TEST-SCRATCH -q
```

Retain compact summaries, hashes, requests, frozen method/selection protocols
and failed attempts. After deleting full traces, mark summaries as requiring
full reconstruction before verification or qualification. A full adapter for
candidate-owned actuator feedback and applied CAN remains separate work.
The narrower [historical actuation audit](LEGACY_NNFF_ACTUATION.md) now checks
original TI/stock counts and feedback, preserving remaining rounding failures.
